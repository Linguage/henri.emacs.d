# Org-roam 日常使用手册

这篇文档回答三个问题：

1. 一条内容应该放在哪里？
2. 什么时候应该创建节点？
3. 节点之间应该怎么连接？

Org-roam 在这套配置里是长期知识库。它不是任务系统，不是日记系统，也不是正式论文阅读卡系统。简单记：

| 内容 | 放哪里 | 原因 |
|------|--------|------|
| 要完成的行动、截止日期、提醒 | Agenda | 需要被调度和追踪 |
| 今天发生了什么、做了什么、感受如何 | Journal | 这是经历档案 |
| 今天冒出的概念、线索、待抽取节点 | Roam daily | 这是知识入口 |
| 会反复回看、会和别的内容发生关系的知识 | Org-roam | 需要被链接和沉淀 |
| 正式文献阅读卡、Citar notes | `Academic/Reading/` | 这是文献笔记真源 |

判断一句话：**任务进 Agenda，经历进 Journal，长期知识进 Org-roam，正式文献笔记进 Academic。**

---

## 1. 基本入口

最常用的只有三个：

| 快捷键 | 用途 |
|--------|------|
| `C-c n f` | 查找或创建节点 |
| `C-c n i` | 在当前笔记中插入节点链接 |
| `C-c n j` | 写今天的 Roam daily |

其他入口：

| 快捷键 | 用途 |
|--------|------|
| `C-c n b` | 打开反链 buffer |
| `C-c n c` | 手动选择模板 capture |
| `C-c n g` | 查看 graph |
| `C-c n t` | 打开今天的 daily note |
| `C-c n y` | 打开昨天的 daily note |
| `C-c n m` | 打开明天的 daily note |
| `C-c n E` | 从当前 daily / inbox heading 抽取为长期 note |
| `C-c n v` | 切换 seedling / budding / evergreen |
| `C-c n d` | 打开 Roam 根目录 |
| `C-c n x` | 打开 Roam inbox 目录 |
| `C-c n ?` | 查看 capture template key |

如果节点不显示，先执行 `M-x org-roam-db-sync`。仍然不显示时，检查文件是否在 `Roam/` 下、文件顶部是否有 `:ID:`。

没有显式 `#+SETUPFILE` 主题的 Org 文件导出 HTML 时，默认采用通用 `Henri Notes` 主题；这只影响导出的 HTML，不会把 `#+SETUPFILE` 写回源 Org 文件。若临时想换主题，用 `C-c m h w` 选择主题导出。

## 2. 内容放哪里

Org-roam 的目录按“用途”分，不按学科分。不要建成：

```text
Roam/math/
Roam/history/
Roam/ai/
Roam/emacs/
```

当前配置固定使用：

| 目录 | 放什么 | 不放什么 |
|------|--------|----------|
| `Roam/daily/` | 当天冒出的想法、线索、待抽取节点 | 完整人生流水、正式日记 |
| `Roam/inbox/` | 临时想法、网页摘录、语音转写、没来得及判断的材料 | 已经成熟的概念节点 |
| `Roam/notes/` | 长期概念、方法、判断、术语 | 单篇资料摘录、项目 TODO |
| `Roam/references/` | 书、文章、网页、视频、非正式资料节点 | 正式 Citar 文献阅读卡 |
| `Roam/projects/` | 有明确产出的长期项目背景、目标、关键节点 | 具体下一步行动 |
| `Roam/people/` | 人物、作者、同事、思想源头 | 人物相关的所有材料堆积 |
| `Roam/maps/` | MOC / Map of Contents，主题工作台 | 单个概念正文 |

目录只管用途，主题关系靠链接和标签表达。比如“AI 编程工作流”可以同时和 `:ai:`、`:software:`、`:writing:` 相关，但文件仍然应该根据用途放到 `notes/`、`projects/` 或 `maps/`。

## 3. 节点类型怎么选

创建新节点时会要求输入 template key。忘记时按 `C-c n ?`。

| Key | 模板 | 落点 | 适合内容 |
|-----|------|------|----------|
| `n` | note / 概念笔记 | `Roam/notes/${slug}.org` | 概念、判断、方法、反复出现的想法 |
| `i` | inbox / 临时收集 | `Roam/inbox/${slug}.org` | 暂时没判断、先收起来的想法、摘录、转写 |
| `r` | reference / 资料笔记 | `Roam/references/${slug}.org` | 网页、视频、书、文章、非正式摘录 |
| `p` | project / 项目笔记 | `Roam/projects/${slug}.org` | 有明确产出的项目 |
| `m` | map / 索引地图 | `Roam/maps/${slug}.org` | 主题入口、知识地图、工作台 |
| `e` | person / 人物笔记 | `Roam/people/${slug}.org` | 作者、研究者、协作者、思想来源 |

Daily 是 org-roam dailies 的独立模板，key 是 `d`，通常通过 `C-c n j` 使用，落点是 `Roam/daily/YYYY-MM-DD.org`。

普通节点默认带 `:seedling:`，表示刚抽出来的想法。写清楚“是什么 / 为什么重要”并至少连到一个旧节点后，可用 `C-c n v` 切到 `:budding:`；被 map 引用、反复被复用后再切到 `:evergreen:`。

### 3.1 `n` 概念笔记

适合写“以后还会用来思考的东西”。

例子：

```text
规格设计
验证机制
Org-roam
铁路扣件系统退化
AI 编程工作流
```

一条好的概念笔记通常包含：

```org
* 我的定义

* 为什么重要

* 相关例子

* 相关节点
```

不要一想到什么就建 `notes/`。先放 daily 或 inbox，等它反复出现、值得复用，再抽出来。

抽取时在 daily / inbox 的当前 heading 上按 `C-c n E`，输入目标 note 名；命令会创建 `Roam/notes/` 节点，把当前 subtree 内容带过去，并在原 heading 下留下回链。

### 3.2 `r` 资料笔记

适合承载外部材料。比如网页、视频、书、一篇文章、一份报告。

例子：

```text
org-roam-user-manual
recoltes-et-semailles
youtube-talk-about-ai-agents
```

资料笔记不要只摘录。至少写一段“我的理解”，并链接到相关概念：

```org
* Metadata
- Source:
- Author:
- Date:
- Type:

* 摘要

* 我的理解
- 这份资料支持了 [[id:...][规格设计]] 中关于验收标准的判断。

* 相关节点
```

正式文献阅读卡仍然放 `Academic/Reading/`。`Roam/references/` 只放通用资料节点和非正式资料线索。

### 3.3 `p` 项目笔记

适合写有明确产出的项目，不适合写单个 TODO。

例子：

```text
henri.emacs.d 写作系统
博士论文第一稿
博客发布流程
AI 编程工作流整理
```

项目笔记放背景、目标、设计判断、关键资料和关键概念。具体行动仍然进 Agenda。

```org
* 目标

* 当前状态

* 下一步
- 这里只放方向；真正要提醒的行动进 Agenda。

* 相关节点
- [[id:...][规格设计]]
- [[id:...][Org-roam 日常使用]]
```

### 3.4 `m` Map / MOC

Map 是主题工作台，不是目录。它回答“我从哪里进入这个主题”。

建议先建这些：

```text
Emacs 系统地图
AI 编程地图
博士论文地图
读书地图
生活系统地图
```

示例：

```org
#+title: AI 编程地图
#+filetags: :map:ai:software:

* 核心概念
- [[id:...][规格设计]]
- [[id:...][验证机制]]
- [[id:...][上下文压缩]]

* 工具
- [[id:...][Claude Code]]
- [[id:...][GitHub Copilot]]

* 项目
- [[id:...][henri.emacs.d 写作系统]]

* 资料
- [[id:...][一篇关于 agents 的文章]]
```

以后不知道从哪里开始，就打开对应 map。

### 3.5 `e` 人物笔记

人物节点适合承载“这个人和哪些想法、作品、项目有关”。

例子：

```text
费曼
格罗滕迪克
某位导师
某位协作者
```

人物节点里不要堆所有材料。它更像一个入口：

```org
* 简介

* 关键思想/事件

* 相关节点
- [[id:...][某本书]]
- [[id:...][某个方法]]
- [[id:...][某个项目]]
```

## 4. 从想法到节点

日常不要急着分类。先让想法有地方落下。

### 4.1 当天想到的东西

按：

```text
C-c n j
```

写到今天的 Roam daily：

```org
* 今日记录
- 配置了 org-roam 的时间元数据
- 读了一段关于 Zettelkasten 的文章

* Done
- 修复了 `C-c n ?` 模板提示

* 想法
- [[id:...][规格设计]] 本质上是在定义“什么算做对”
- Org-roam 更像知识工程底座，不是漂亮笔记软件

* 待抽取节点
- 验证机制
- Emacs 写作系统
```

`待抽取节点` 很重要。它是从流水过渡到长期节点的桥。

### 4.2 没时间判断的材料

放 `Roam/inbox/`。比如网页摘录、语音转写、突然冒出来的一段想法。

原则：inbox 可以乱，但不能永久不清。每周整理一次。

### 4.3 什么时候创建正式节点

用“三次出现原则”：

如果一个想法在 daily、项目、阅读里反复出现三次，就该变成节点。

也可以用这几个判断：

| 情况 | 处理 |
|------|------|
| 只是今天的一句感受 | Journal |
| 是今天冒出来但还没成熟的线索 | Roam daily |
| 以后可能还要找，但暂时没判断 | Roam inbox |
| 已经能说清楚“它是什么 / 为什么重要” | `notes/` |
| 是外部资料 | `references/` |
| 会产出东西 | `projects/` |
| 是主题入口 | `maps/` |

## 5. 如何建立关联

Org-roam 的价值不在“有很多文件”，而在“节点之间能互相解释”。

### 5.1 插入正向链接

在任何 Org-roam 文件里按：

```text
C-c n i
```

选择已有节点，或输入新节点名创建。

写链接时不要只列名字，最好写出关系：

```org
- [[id:...][验证机制]] 是 [[id:...][规格设计]] 的落地方式。
- [[id:...][Org-roam daily]] 负责捕获待抽取节点，最终沉淀到 [[id:...][长期概念节点]]。
```

### 5.2 看反链

打开一个节点后按：

```text
C-c n b
```

反链回答：“有哪些地方提到了这个节点？”

常见用法：

| 场景 | 做法 |
|------|------|
| 想知道一个概念从哪里来 | 打开概念节点，看反链里的 daily / reference |
| 想知道一个项目牵涉哪些知识 | 打开 project 节点，看反链 |
| 想整理主题 | 打开 map，补充还没挂上来的相关节点 |

### 5.3 常见连接模式

**概念连接概念**：

```org
[[id:...][规格设计]] -> [[id:...][验收标准]] -> [[id:...][验证机制]]
```

适合表达推理链。

**资料支持概念**：

```org
[[id:...][某篇文章]] 支持/反驳/补充 [[id:...][AI 编程工作流]]
```

适合读书、文章、视频整理。

**项目调用概念和资料**：

```org
[[id:...][henri.emacs.d 写作系统]]
- 依赖 [[id:...][Org-roam]]
- 使用 [[id:...][规格设计]]
- 参考 [[id:...][某篇配置文章]]
```

适合把工作和知识连起来。

**Map 聚合主题**：

```org
[[id:...][AI 编程地图]]
- 核心概念
- 工具
- 项目
- 资料
```

适合做入口。

### 5.4 每个节点至少连一个旧节点

新建节点时，问自己：

```text
它解释了哪个旧节点？
它被哪个旧节点解释？
它属于哪个 map？
它来自哪条 daily 或 reference？
```

至少连一个。一个完全孤立的节点，通常还没有进入知识系统。

## 6. 标签怎么用

标签只做粗分类，不要做成另一套目录。

推荐粗标签：

```text
:ai:
:software:
:emacs:
:latex:
:writing:
:reading:
:math:
:railway:
:thesis:
:health:
:history:
:project:
:reference:
:daily:
:map:
```

一条笔记 1 到 3 个标签足够：

```org
#+filetags: :ai:software:writing:
```

不要这样：

```org
#+filetags: :ai-coding-agent-workflow-context-compression:
```

如果一个标签已经细到像一句话，通常应该建成节点，而不是标签。

## 7. 每日和每周工作流

### 7.1 每天 5 分钟

1. `C-c n j` 打开今天的 Roam daily。
2. 把今天冒出的概念、资料线索、待抽取节点写进去。
3. 遇到已有节点，用 `C-c n i` 插入链接。
4. 不急着整理，不追求完整。

每天只要留下能被未来自己找到的线索，就够了。

### 7.2 写正式节点时

1. `C-c n f` 输入节点名。
2. 选择模板 key：`n/i/r/p/m/e`。
3. 写清楚它是什么。
4. 插入至少一个相关节点链接。
5. 如果它属于某个主题，打开对应 map，把它挂进去。

### 7.3 每周整理

每周找一个固定时间，做三件事：

1. 打开最近 7 天的 Roam daily，查看 `待抽取节点`。
2. 把反复出现或已经成熟的内容抽成 `notes/`、`projects/` 或 `references/`。
3. 打开相关 `maps/`，把新节点挂进去。

不要试图一次整理全部历史资料。让系统从现在开始生长。

## 8. 边界和反例

### 8.1 不要把 Roam 当任务系统

这类内容进 Agenda：

```text
明天 10 点检查邮件
周五前提交报告
修复某个 bug
```

Roam project 可以写“为什么要做、怎么判断做对、相关知识是什么”，但具体行动应该由 Agenda 管。

### 8.2 不要把 Roam daily 当 Journal

Journal 写：

```text
今天发生了什么
我的状态如何
这件事对我有什么影响
```

Roam daily 写：

```text
今天冒出的知识线索
以后可能要抽取的概念
临时资料入口
```

### 8.3 不要把所有资料都塞进 `references/`

正式文献阅读卡和 Citar notes 默认归：

```text
Academic/Reading/
```

`Roam/references/` 更适合网页、视频、书目线索、非正式读书摘录，以及会连接到多个概念的通用资料节点。

### 8.4 不要过早建太多节点

坏习惯：

```text
看到一个词就建一个节点
每条摘录都建一个节点
为了图谱好看而疯狂链接
```

好习惯：

```text
先写 daily / inbox
反复出现再抽节点
每个节点连到真实相关内容
```

### 8.5 HTML 导出不要手动复制主题文件头

未显式指定主题的 Org HTML 导出已经默认使用通用 `Henri Notes` 主题。不要为了统一外观手动复制主题文件头；需要固定主题时优先使用普通 HTML 导出，或用 `C-c m h w` 临时选择 `Henri Journal` / Bearblog / ReadTheOrg 等其它主题。

## 9. 第一周启动方案

第 1 天：熟悉入口。

```text
C-c n f
C-c n i
C-c n j
C-c n ?
```

第 2 天：建 5 个 maps。

```text
Emacs 系统地图
AI 编程地图
博士论文地图
读书地图
生活系统地图
```

第 3 到第 5 天：每天只写 Roam daily，不迁移旧资料。

第 6 天：从 daily 里抽 10 个节点。优先抽：

```text
反复出现的概念
正在做的项目
最近读到的重要资料
你总会回头查的判断
```

第 7 天：打开每个 map，把这 10 个节点挂进去。

一周后，目标不是“知识库完整”，而是形成一个能继续长大的骨架。

## 10. 最小使用口诀

```text
每天写 daily。
三次出现就建节点。
新节点至少连一个旧节点。
主题入口放 maps。
任务不要进 Roam。
```
